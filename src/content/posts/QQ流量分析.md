**01 实验环境**

**操作系统：**Windows

**抓包工具：**Wireshark

**网络环境：**校园网

**测试模式：**PC-PC端，PC-手机端



**02 测试流程（以PC-PC为例）**

**提示：**校园网里你的私网 IP 和别人的一样，或者公网出口 IP 一样，你不能直接过滤 `ip.addr == 你的IP`。你需要找出 QQ 这款软件当前正在跟哪台腾讯服务器通信。

```
打开 PowerShell（管理员模式），运行以下命令获取 QQ 当前连接的远程 IP：
Get-NetTCPConnection | Where-Object { $_.OwningProcess -in (Get-Process QQ, QQEX -ErrorAction SilentlyContinue).Id } | Select-Object RemoteAddress, RemotePort

把命令输出结果里那些 腾讯的 IP 地址（通常是 120.233.x.x等）记下来。
```

**开始测试：**

1. 清空 Wireshark 过滤器，或者在上面的过滤器后面加上 `&& tcp.port == 443`。

2. 准备好发图：在 QQ 聊天窗口里选好图片，但先不要点发送。

3. 使用Wireshark 的“重新开始抓包”的功能，清空列表。

4. 在 QQ 里点击发送图片。

5. 图片发送进度条走完后，立刻停止 Wireshark 抓包。

6. 在过滤器里输入：

   text

   ```
   tcp.port == 443 && ip.addr == <你刚才记下的IP>(可能不止一个)
   ```


7. 分析抓包结果

**03 结果分析** 

**03-1 UDP or TCP**

**结论**：现代 QQ 主要使用 **TCP** 协议。通过抓包可以观察到明确的 TCP 流，目标端口多为 443。虽然 QQ 在音视频等极少数场景可能用 UDP，但在日常聊天、传文件的场景下，为了保证可靠性，主要依赖 TCP。

**抓包证据**：图中明确显示了 `Protocol` 列表里全部是 TCP 协议，应用层显示为 TLSv1.2，并且看到了经典的 TCP 三次握手建立连接后的数据交互（`[ACK]`）。

为了使结论更加严谨，我们可以在过滤栏输入`udp.port == 8080`，回车查看传输图片过程中是否使用了UDP协议。

![image-20261021194042826](https://cdn.jsdelivr.net/gh/CheerrightNow/my-blog-images@img/img/img/2026/10/21/afab4b8752fa83e0f202c830d1caca39-image-20261021194042826.png)

**03-2 加密 or 明文**

**结论：**QQ 通信数据大部分已被加密，少部分以明文形式传输。

（极少部分特殊情况个例详见04-2）

**明文数据：**通信时间与频率，通信两端ip地址，SNI 域名等等。

**加密数据及分析**：聊天文字,图片具体内容、格式等等均已被加密。

在抓包列表的 `Protocol` 列，我们看到大量的 `SSL` 和`TLSv1.2`标识，这说明 Wireshark 已经识别出这不是明文协议。

右键点击任意一个TCP包 -> “追踪流” -> “TCP 流”。结果只能看到满屏的乱码，底部“查找”功能同样找不到什么有效信息。

**04 遇到的问题**

**04-1 输入oicq抓不到数据包**

Wireshark 识别协议，靠的是端口号或数据特征。**老版本** QQ 时代，Wireshark 把 UDP 8000 端口直接标记为 `OICQ` 协议。所以输入 `oicq`，它就会把目标端口是 8000 的 UDP 包全筛出来。

但**现版本**的 QQ 变了：

1. 传输层协议变了：新版 QQ 的主业务连接几乎全部转向了 **TCP 443**（为了安全、稳定和穿透防火墙）。
2. 加密方式变了：数据全程被 **TLS 加密**，Wireshark 只能识别出这是加密的 `TLSv1.2` 或 `TLSv1.3` 流量，完全看不到 OICQ 时代的明文特征。

**04-2 意外发现：TCP流报文中个人QQ号多次以明文形式重复出现**

第三次测试发送图片的时候发现我QQ号多次以明文形式出现在TCP流报文中，满脸疑惑？？？**(经多次重复测试，这属于极少数情况)**

**可能的解释：**理论上的绝对加密在实际工程落地时，往往会因为性能优化和特殊架构设计而出现例外。

**04-3**  **手机 QQ 发出的业务流量未被完全捕获**

在尝试通过 Windows 移动热点抓取手机端 QQ 流量时，Wireshark 仅捕获到 DNS 等背景协议，未出现 TCP 443 业务流量。经排查，一个可能原因是Windows 自带热点存在网卡隔离机制，导致手机发出的原始数据帧无法被宿主机抓包驱动完整捕获。
